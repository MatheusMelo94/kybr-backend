# Kybr API

The HTTP API behind Kybr: the seller verification link and the operations panel. This repository holds the backend only; the web frontend calls it server-to-server.

## Stack

- Java 25, Spring Boot 4 (Spring MVC, Spring Security, Spring Data MongoDB, Actuator)
- MongoDB 8 as a replica set (MongoDB Atlas in the cloud)
- Maven (through the `./mvnw` wrapper), Docker and Docker Compose
- OpenAPI 3.1, generated by springdoc

## Running locally

Prerequisites: a JDK 25 (for example Temurin 25). Docker with Compose v2 is optional.

```bash
./run-local.sh              # MongoDB in Docker (replica set rs0), then the API with the "local" profile
./run-local.sh --no-mongo   # no Docker: use the MongoDB replica set in MONGODB_URI (environment or .env)
./run-local.sh --docker     # the full containerised stack (API + MongoDB)
./run-local.sh --down       # stop the compose stack (the MongoDB volume is kept)
```

On first run, `run-local.sh` creates a gitignored `.env` with random development values for the required secrets. Existing values are never changed. To override anything else, copy the variable from `.env.example` into `.env`.

The API listens on `http://localhost:8080`:

```bash
curl -i http://localhost:8080/livez
```

### Without Docker

MongoDB must run as a replica set (the API uses transactions). With a local `mongod --replSet rs0` that has been initiated once (`rs.initiate()`):

```bash
MONGODB_URI='mongodb://127.0.0.1:27017/kybr?replicaSet=rs0' ./run-local.sh --no-mongo
```

## Configuration

Configuration comes from environment variables. `.env.example` lists all of them. Locally, `run-local.sh` reads `.env`. In staging and production every secret is required and has no default, so the API refuses to start without them.

| Variable | Required | Description |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | no | `local`, `docker`, `staging` or `prod` (`run-local.sh` sets it) |
| `PORT` | no | API port (default `8080`) |
| `MANAGEMENT_PORT` | no | Internal health and metrics port (default `8081`), never published |
| `MONGODB_URI` | cloud | MongoDB connection string (a replica set) |
| `KYBR_BFF_KEY_CURRENT` | yes | Shared key for calls from the frontend server (base64url, at least 32 random bytes) |
| `KYBR_BFF_KEY_PREVIOUS` | no | The previous shared key, set only while rotating |
| `KYBR_HASH_SECRET` | yes | HMAC secret (base64url, at least 32 random bytes) |
| `KYBR_HASH_SECRET_PREVIOUS` | no | The previous HMAC secret, set only while rotating |
| `KYBR_IDEMPOTENCY_ENC_KEY` | yes | Encryption keyset for stored responses (a base64 Tink `AES256_GCM` JSON keyset) |
| `KYBR_CLIENT_IP_PLATFORM_HEADER` | no | The hosting platform's client-IP header (empty locally) |

Generate a 32-byte value with `openssl rand 32 | basenc --base64url`.

## API

| Method | Path | Auth | Description |
|---|---|---|---|
| `GET` | `/livez` | none | Liveness probe: `200` with the status only |

Readiness and metrics are served on the internal management port (`8081`) for the hosting platform's checks. They are not part of the public API.

Every response carries an `X-Request-Id` header. Errors use one JSON envelope: `code`, `message` and, when known, `field`.

### OpenAPI

The contract of record is [`docs/openapi.yaml`](docs/openapi.yaml). `./mvnw verify` fails if the generated document differs from the committed file. After an intended API change, regenerate the file and commit it:

```bash
./mvnw verify -Dopenapi.write=true
```

With the `local` profile, the live document is served at `http://localhost:8080/v3/api-docs` (and `/v3/api-docs.yaml`). It is disabled in staging and production.

## Testing

```bash
./mvnw test                          # unit tests
./mvnw verify                        # unit and integration tests
./mvnw test -Dtest=ClassName         # one unit test class
./mvnw verify -Dit.test=ClassNameIT  # one integration test class
```

By default, integration tests start MongoDB in a container (Testcontainers), so Docker must be running. Without Docker, point them at a MongoDB replica set you run yourself:

```bash
KYBR_TEST_MONGO_URI='mongodb://127.0.0.1:27017/?replicaSet=rs0' ./mvnw verify
```

The tests use the `kybr-test` database there, and they may drop its collections. To keep parallel runs on one server apart, set a different database name with `KYBR_TEST_MONGO_DB`. Tests generate their own secrets in memory, so no `.env` is needed.

## Project layout

```
src/main/java/com/matheusmelo/kybr/
  config/       Spring configuration, servlet filters and logging setup
  controller/   REST endpoints
  dto/          Request and response records (the public contract)
  exception/    Error codes, exceptions and the global error handler
  model/        Domain types and persisted documents
  repository/   Spring Data MongoDB repositories
  service/      Business logic
  util/         Pure, stateless helpers
```

Architecture rules (layer boundaries) are enforced by ArchUnit tests under `src/test/java/.../arch/`.
